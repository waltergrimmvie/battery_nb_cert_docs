Battery NB — first design
==========================

This file is the design draft for the cert desk. startup/startup.js is the
only entry. It calls the other procedures. Do not boot the page from anywhere
else.

Boot
----
1. Read the signed-in name from IndexedDB.
   Database: battery_nb_cert_docs
   Store: session
   Key: user
2. If that name is missing, show setup/login_user.js.
   The login page is a dropdown of known names and an Enter button.
   There is no field where a name can be typed.
   Known names: Judy, Marcus, Wei, Walter.
3. If the name is already in IndexedDB, skip login.
4. The next procedure is main_page/construct_main_page.js.

Main page
---------
The page is two rows and fills the viewport.

Row 1. Menu bar, full width.
Row 2. Fills the remaining width and height. Two columns and a slider
       between them.
       Left:  tree container
       Middle: slider
       Right: content container

The slider drags. On a narrow screen the two panes stack and the slider
still divides them.

Menu bar
--------
menu_bar/construct_design builds the bar:
- a signed-in field with the current name
- an icon of three heads, shifted up, with the online count written under them
  in the Battery NB cert type

menu_bar/online_users.js keeps the array of everyone currently online.
When somebody logs on or off, that array is replaced and the number on
the icon changes.

The icon opens a designed mega menu, not a native HTML dropdown.
menu_bar/populate fills that menu with everyone currently logged in on
the desk. Each person keeps the red / green toggle.

Tree and content
----------------
The tree is read from the documents directory.
- Each directory is a top-level node, using the directory name.
- Each Word document in that directory is a child node.
Clicking a document opens its text in the content container.
Clicking a directory only opens or closes its documents.

Desk
----
The WebSocket room is unchanged. The mega menu is the live list of who
is on the desk. Names are text, never HTML.

Documents — one-time upload
---------------------------
The Word files under documents/ are uploaded to the Cloudflare Worker
assets (public/documents/) exactly once.

After that upload has landed on the live Worker:
- Do not replace, rename, or republish those documents from Git again.
- Do not run scripts/index-documents.mjs in a way that overwrites
  public/documents/.
- A later GitHub push must not overwrite the documents already on
  Cloudflare.
- Once the files are confirmed on the live site, remove the document
  binaries from Git. They stay on the Cloudflare assets from that one
  upload.
- Future work on the checklist or the page shell does not touch the
  uploaded Word files.

Marker: documents-uploaded.txt in the repo root. When that file exists
and contains "locked", the index script refuses to wipe or copy over
public/documents/.
